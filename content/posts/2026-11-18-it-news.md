안녕하세요! DevGear의 DevMonster입니다! 오늘은 11월 18일, 하루 사이에 나온 IT 뉴스 다섯 가지를 정리합니다. 엔비디아의 깜짝 실적부터 자바의 빠른 Base64 디코더에서 나온 취약점, 대형 사이트에 악성 코드를 뿌린 외부 스크립트, 마이크로소프트의 새 모델 일곱 개, 애플의 서비스 장애까지 '빨라지려고 넣은 것과 믿고 맡긴 것'이 어떻게 결과를 갈랐는지 살펴보겠습니다.

## 1. 반도체: "CEO는 없어도 매출은 두 배, 엔비디아 3분기 실적"

**핵심 뉴스:** 엔비디아가 2027 회계연도 3분기 매출 **1,158억 달러**를 발표했습니다. 지난해보다 **103**% 늘었고, 월가 예상치였던 약 1,087억 달러를 크게 넘었습니다. (Constellation Research)

이 가운데 데이터센터 매출은 **1,076억 달러**로 1년 전보다 **110**%, 직전 분기보다 21% 늘었습니다. 4분기 매출 전망은 약 **1,300억 달러**로 제시했는데, 이 숫자에는 중국 데이터센터 매출을 아예 넣지 않았습니다. 다음 회계연도 매출 성장률 전망도 약 70%에서 **75**%로 올렸습니다. (Constellation Research)

11/13과 11/17에 전해 드린 젠슨 황 사임 이야기의 후속도 함께 나왔습니다. 하비 존스 이사회 의장은 황을 다시 CEO로 세울 생각이 없다고 밝혔고, 임시 CEO **콜렛 크레스**는 로드맵이 예정대로 진행되고 있다고 말했습니다. 황은 X에 이사회가 회사에 가장 좋다고 판단하면 돌아오겠다는 글을 올렸고, 엔비디아는 자사주 매입 한도를 **1,500억 달러** 늘렸습니다. (Constellation Research)

> **Dev Monster의 시선:** 숫자보다 먼저 눈에 들어온 건 4분기 전망에서 **중국 매출을 0으로** 잡았다는 대목이었습니다. 큰 시장 하나를 통째로 빼고도 1,300억 달러를 예상한다는 건, 그만큼 다른 지역의 주문이 밀려 있다는 뜻으로 읽힙니다. 반대로 주가는 지난 한 달 동안 28% 떨어졌다고 하니, 실적과 리더십 공백 중 시장이 어느 쪽에 더 무게를 둘지 궁금합니다.

## 2. 보안: "빠르게 하려던 어셈블리 한 줄, 자바 서버의 문이 열렸다"

**핵심 뉴스:** OpenJDK의 **Base64 디코더**에서 로그인 없이 원격 코드 실행까지 가능한 취약점 **Java4Shell**(CVE-2026-114938)이 공개됐습니다. 연구진은 CVSS v4.0 기준 **9.2**점으로 평가했습니다. (Qualys)

문제는 Base64 해독을 빠르게 하려고 손으로 짠 **AVX-512** 어셈블리 코드에 있습니다. 짧고 잘못된 입력을 넣으면 자바가 오류를 내기 전에 버퍼 끝을 넘어 **62바이트**를 덮어써 버립니다. 영향을 받는 건 17.0.6 이후의 패치되지 않은 OpenJDK 계열 빌드로 21, 25, 27이 모두 포함되고, AVX-512 VBMI를 지원하는 인텔 제온과 AMD EPYC·Ryzen(Zen 4 이후)에서만 터집니다. ARM64나 해당 명령어가 없는 x86 CPU, 그리고 17.0.6 이전 버전은 영향이 없습니다. (Qualys)

연구진은 기본 설치 상태의 **Keycloak**, Jira, Confluence, Jenkins 등에서 로그인 전 원격 코드 실행을 시연했습니다. 오라클은 17.0.21.1, 21.0.13.1, 25.0.5.1 등 패치 버전을 내놓았고, 바로 패치할 수 없다면 JVM 옵션 -XX:-UseBASE64Intrinsics 로 문제의 빠른 디코더를 끄는 방법이 권장됩니다. 11월 17일 기준으로 실제 공격 사례는 확인되지 않았습니다. (Qualys)

> **Dev Monster의 시선:** 저도 JWT를 다루다 보면 Base64 디코딩을 아무 생각 없이 쓰는데, 같은 자바 코드라도 **어떤 CPU에서 도느냐**에 따라 위험이 갈린다는 점이 충격이었습니다. 제 노트북에서는 멀쩡해도 클라우드의 최신 x86 인스턴스에서는 취약할 수 있다는 뜻이니까요. 제 연습 서버가 어떤 JDK 빌드와 CPU 위에서 돌아가는지, java -version 결과와 인스턴스 사양부터 같이 확인해 보려 합니다.

## 3. 웹: "믿고 불러온 스크립트가, 대형 사이트 수백 곳에 악성 코드를 실었다"

**핵심 뉴스:** A/B 테스트 플랫폼 **Optimizely**의 취약점이 악용돼, 고객사 웹사이트에 악성 자바스크립트가 실렸습니다. Report URI 분석에 따르면 BBC, CNN, Zoom, GitLab, IKEA 등 **178**개 조직의 스크립트가 감염됐습니다. (SecurityWeek)

공격자는 고객이 직접 자바스크립트를 넣는 선택 항목에 악성 코드를 심었고, 이 코드는 모든 페이지에서 실행됐습니다. 변조된 파일이 Optimizely의 CDN에서 그대로 내려왔기 때문에 사이트들은 이를 믿을 수 있는 코드로 받아들였습니다. 코드는 암호화폐 지갑 주소를 바꿔치기하고, 결제 카드 정보를 가로채고, 쿠키와 화면을 수집할 수 있었으며, 월요일 저녁까지 약 **7,000달러**어치 암호화폐가 공격자에게 넘어갔습니다. (SecurityWeek)

첫 주입은 11월 16일 04시 21분(UTC)이었고, 같은 날 21시 52분에는 정리되지 않은 스크립트가 하나만 남았습니다. 아이폰·아이패드 사용자에게는 iOS 익스플로잇 킷이 전달됐다는 보고도 있지만, 실제 감염 성공은 아직 입증되지 않았습니다. Optimizely는 취약점을 고치고 주입된 코드를 지웠다고 밝혔습니다. (SecurityWeek)

> **Dev Monster의 시선:** Report URI의 스콧 헬름이 말한 '내 코드와 서버가 뚫리지 않아도 사이트는 뚫릴 수 있다'는 문장이 오래 남았습니다. 실험 도구처럼 내용이 자주 바뀌는 스크립트는 파일 해시를 고정하는 방식으로 막기 어렵다 보니, 결국 **어떤 외부 스크립트가 내 페이지에 들어와 있는지**를 아는 것부터가 출발점으로 보입니다. 제 블로그에 붙은 분석·댓글 스크립트가 몇 개인지 먼저 세어 보고 싶어졌습니다.

## 4. AI: "코딩부터 보안, 음성까지, 마이크로소프트가 모델 일곱 개를 내놨다"

**핵심 뉴스:** 마이크로소프트가 **Ignite 2026**에서 코딩, 보안, 이미지, 음성, 전사, 의사결정용 자체 **MAI** 모델 일곱 개를 한꺼번에 발표했습니다. (Thurrott.com)

코딩 모델 **MAI Code 2**는 경쟁 최상위 모델 대비 96~98% 수준의 성능을 훨씬 낮은 가격에 낸다고 주장했고, 보안 모델 MAI Cyber 2 Flash와 이미지 편집 모델 MAI Image 2.7, 실시간 음성 모델 **MAI Realtime 1**도 함께 나왔습니다. MAI Realtime 1은 음성 1분당 0.01달러부터 시작합니다. 다만 성능 비교는 모두 마이크로소프트가 밝힌 수치로, 외부에서 검증된 결과는 아닙니다. (Thurrott.com)

일곱 모델은 모두 마이크로소프트의 2세대 데이터센터 가속기 **Maia 200** 위에서 실제 서비스되고 있습니다. 마이크로소프트는 고객 맞춤형 모델도 만들기 시작했고, 기업이 자기 Azure 환경에 모델을 직접 배포하고 고칠 수 있는 'MAI Licensed Weights'도 곧 내놓을 예정이라고 밝혔습니다. (Thurrott.com)

> **Dev Monster의 시선:** 가장 흥미로웠던 건 일곱 모델이 모두 **자체 칩**인 Maia 200에서 돌아간다는 점이었습니다. 모델과 칩을 한 회사가 같이 만들면, 같은 모델이라도 다른 클라우드에서는 같은 속도와 가격이 나오지 않을 수도 있습니다. 회사가 직접 낸 비교표 말고, 외부 벤치마크에서 MAI Code 2가 실제 코딩 과제를 어떻게 풀어내는지 결과가 나오길 기다려 보려 합니다.

## 5. 플랫폼: "내부 업데이트 하나에, 애플 로그인과 결제가 멈췄다"

**핵심 뉴스:** 11월 17일 오전 9시 45분(미국 태평양 시간)쯤부터 **Apple Pay**, iCloud, App Store, **Sign in with Apple** 등 애플의 여러 서비스가 2시간 넘게 장애를 겪었습니다. (Tom's Guide)

장애 신고 사이트 Down Detector에서는 Apple Pay 신고만 몇 분 만에 약 **2,000**건까지 치솟았습니다. 이후 애플 상태 페이지에는 iCloud 계정 로그인, App Store Connect, **Xcode Cloud** 같은 개발자용 서비스까지 문제가 있는 항목으로 올라왔습니다. (Tom's Guide)

애플은 오후 12시 7분쯤 '오늘 아침 내부 업데이트로 일부 장애가 있었고, 많은 시스템이 복구됐다'고 밝혔습니다. 사이버 공격이 아니라 내부 업데이트가 원인이라는 설명이지만, 어떤 업데이트였는지는 공개하지 않았습니다. (Tom's Guide)

> **Dev Monster의 시선:** 웹개발자에게 가장 직접 닿는 건 **Sign in with Apple**이 멈췄다는 부분이었습니다. 소셜 로그인만 열어 둔 사이트라면 애플 쪽 장애 동안 그 사용자들은 아예 들어올 수 없었을 텐데, 이때 화면에 '잠시 후 다시 시도해 주세요'처럼 이유를 알려 주는지, 그냥 빈 화면이 뜨는지는 서비스마다 다를 것 같습니다. 제 연습 프로젝트의 소셜 로그인 콜백이 외부 실패를 어떻게 보여 주는지 한번 일부러 실패시켜 보고 싶습니다.

오늘 뉴스는 빨라지려고 넣은 것과 믿고 맡긴 것이 결과를 가른 하루였습니다. **엔비디아**는 리더십 공백 속에서도 매출을 두 배로 키웠고, 마이크로소프트는 자체 칩 위에서 **MAI** 모델 일곱 개를 내놓았습니다. 반대로 **Java4Shell**은 속도를 위해 손으로 짠 코드에서, **Optimizely** 사고는 믿고 불러온 외부 스크립트에서, **애플** 장애는 내부 업데이트 하나에서 시작됐습니다.

신입 웹개발자로서 가장 구체적으로 남은 건 '내가 직접 쓰지 않은 코드도 내 서비스의 일부'라는 점입니다. JDK 안의 어셈블리, 페이지에 붙인 실험용 스크립트, 로그인을 맡긴 외부 계정 서비스는 모두 제가 고르기만 했을 뿐인데, 문제가 생기면 사용자는 제 사이트에서 그 결과를 겪게 됩니다. 그래서 무엇에 기대고 있는지 목록으로 알고 있는 것만으로도 사고가 났을 때 대응 속도가 달라질 것 같습니다.
