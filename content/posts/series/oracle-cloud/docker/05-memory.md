## 이 글에서 할 일

서버 한 대에 Java 앱 여러 개, PostgreSQL, nginx가 함께 살면, 한 앱이 메모리를 다 써 버릴 때 다른 앱까지 멈춥니다. 이 글에서는 메모리를 나눠 주는 두 가지 장치와 그 숫자를 정하는 원리를 설명합니다.

## 상한을 두지 않으면 생기는 일

Java(JVM)는 힙 상한을 주지 않으면 사용 가능한 메모리를 보고 스스로 최대치를 정합니다. 기본값은 메모리의 1/4 정도입니다. 10GB 서버라면 앱 하나가 2GB 넘게 쓸 수 있고, 앱이 여러 개면 합쳐서 서버 메모리를 넘길 수 있습니다.

## 두 가지 상한

| 장치 | 설정 | 막는 것 |
|---|---|---|
| Java 힙 상한 | Dockerfile의 `-Xmx` | Java 객체가 쓰는 메모리(힙)의 최대치 |
| 컨테이너 상한 | compose의 `mem_limit` | 컨테이너 전체(힙 + 힙 밖)가 쓰는 메모리의 최대치. 넘으면 컨테이너가 강제 종료 |

```dockerfile
ENV JAVA_OPTS="-Xms256m -Xmx512m"
```

```yaml
    mem_limit: 768m
```

### 왜 컨테이너 상한이 힙 상한보다 커야 하나

Java는 힙 말고도 메모리를 씁니다.

```text
컨테이너 메모리 =  힙 (-Xmx)
                + 메타스페이스 (클래스 정보)
                + 스레드 스택 (요청을 처리하는 스레드마다)
                + 코드 캐시 (JIT 컴파일 결과)
                + 기타
```

컨테이너 상한을 힙과 같게 잡으면, 힙은 여유가 있어도 힙 밖 메모리 때문에 컨테이너가 강제 종료됩니다. 그래서 **컨테이너 상한 = 힙 상한 + 힙 밖 여유**로 정합니다. 작은 Spring 앱이라면 힙 밖 여유를 256MB 정도로 시작하고, 실제 사용량을 보며 조정합니다.

| 예 | 힙 상한 (`-Xmx`) | 컨테이너 상한 (`mem_limit`) | 힙 밖 여유 |
|---|---|---|---|
| 앱 A | 512MB | 768MB | 256MB |
| 앱 B | 384MB | 640MB | 256MB |

## 지금 얼마나 쓰고 있나

```bash
docker stats --no-stream --format '{{.Name}} {{.MemUsage}}'
```

```text
app-a 321.2MiB / 768MiB
app-b 242.9MiB / 640MiB
```

`/` 앞이 지금 사용량, 뒤가 `mem_limit`입니다. 평소 사용량이 상한에 가깝다면 여유가 부족한 것입니다. 앱을 실제로 써 보면서(로그인, 목록 조회 등) 사용량이 어디까지 오르는지 봅니다.

## 서버 전체 메모리 계획

앱의 상한을 더해 서버 메모리 안에 들어오는지 확인합니다. [사용량 확인 글](/posts/oracle-cloud-linux-resources)의 계획표를 함께 갱신합니다.

| 사용처 | 최대 |
|---|---|
| 앱 A 컨테이너 | 768MB |
| 앱 B 컨테이너 | 640MB |
| PostgreSQL (`shared_buffers` 128MB + 연결별 메모리) | 수백 MB |
| nginx, 운영체제, 기타 | 수백 MB |
| **합계** | 서버 메모리보다 충분히 작게 |

새 앱을 추가할 때도 같은 방식으로 상한을 정하고 이 표에 한 줄을 더합니다.

## 상한에 걸리면

컨테이너가 상한을 넘으면 리눅스가 강제로 종료합니다(**OOM Kill**, Out Of Memory). `restart: unless-stopped`라서 자동으로 다시 시작되지만, 사용자 요청은 그 순간 실패합니다.

```bash
docker inspect myapp --format '{{.State.OOMKilled}} {{.RestartCount}}'
```

| 결과 | 의미 |
|---|---|
| `false 0` | 강제 종료된 적 없음 |
| `true ...` | 마지막 종료가 메모리 초과 때문 |
| 재시작 횟수가 계속 늘어남 | 앱이 반복해서 죽고 있음. 로그와 함께 원인 확인 |

메모리 초과라면 `-Xmx`와 `mem_limit`을 함께 늘립니다. 힙에서 `OutOfMemoryError`가 나는 경우(로그에 표시)는 힙이 부족한 것이고, 로그에 오류 없이 컨테이너만 종료됐다면 힙 밖 여유가 부족한 경우가 많습니다.

## 정리

- Java 앱은 `-Xmx`로 힙 상한을, compose의 `mem_limit`으로 컨테이너 상한을 둡니다.
- 컨테이너 상한은 **힙 + 힙 밖 여유**로 정합니다.
- `docker stats`로 사용량을 보고, OOM 종료가 생기면 두 값을 함께 조정합니다.
