## 이 글에서 할 일

이 시리즈는 Java 웹 앱을 Docker **컨테이너**로 실행합니다. 이 장에서는 Docker 설치부터 운영까지 다룹니다. 이 글에서는 먼저 용어와 쓰는 이유를 정리합니다.

## Docker가 해결하는 문제

Java 웹 앱을 서버에서 실행하려면 Java 17, Tomcat 10.1, 설정 파일, 빌드된 war 파일이 모두 맞아야 합니다. 이 준비를 서버마다 손으로 하면 다음 문제가 생깁니다.

- "내 PC에서는 되는데 서버에서는 안 돼요" (버전이 다름)
- 앱 A는 Tomcat 9, 앱 B는 Tomcat 10.1이 필요함 (한 서버에서 충돌)
- 서버를 새로 만들면 설치 과정을 처음부터 반복해야 함

Docker는 **앱과 앱이 실행되는 데 필요한 모든 것을 하나로 포장**합니다. 포장된 것은 어느 서버에서든 똑같이 실행됩니다.

## 용어: 붕어빵으로 이해하기

| 용어 | 뜻 | 비유 |
|---|---|---|
| **Dockerfile** | 이미지를 만드는 방법을 적은 파일 | 붕어빵 틀 설계도 |
| **이미지(image)** | Dockerfile대로 만든 실행 준비물 묶음. 읽기 전용 | 붕어빵 틀 |
| **컨테이너(container)** | 이미지를 실행한 것. 실제로 돌아가는 앱 | 틀로 찍어 낸 붕어빵 |
| **docker compose** | 컨테이너 실행 옵션을 파일(`docker-compose.yml`)로 적어 두고 한 번에 실행 | 붕어빵 가게 운영 매뉴얼 |
| **레지스트리** | 이미지를 저장하고 공유하는 곳. Docker Hub가 대표적 | 틀 판매점 |

이미지 하나로 컨테이너를 여러 개 띄울 수 있고, 컨테이너를 지워도 이미지는 남아 있어 다시 띄울 수 있습니다.

## 가상 머신과 무엇이 다른가

| | 가상 머신 (Oracle Cloud 인스턴스 같은) | 컨테이너 |
|---|---|---|
| 포함하는 것 | 운영체제 전체 | 앱과 필요한 라이브러리만 (운영체제 커널은 서버 것을 함께 씀) |
| 크기 | 수 GB | 수백 MB |
| 시작 시간 | 수십 초 ~ 분 | 수 초 |

그래서 서버 한 대(가상 머신) 위에 컨테이너 여러 개를 가볍게 올릴 수 있습니다.

## 무엇을 Docker로 실행할까

서버의 모든 것을 Docker로 실행할 필요는 없습니다. 이 시리즈는 다음 기준으로 나눕니다.

| 대상 | 실행 방식 | 이유 |
|---|---|---|
| Java 앱 (Tomcat) | Docker | Tomcat 버전이 앱마다 다를 수 있고, 배포를 `docker compose up -d --build` 한 줄로 단순화 |
| PostgreSQL | 서버에 직접 설치 | 여러 앱이 함께 쓰는 공용 데이터 저장소 ([선택 기준](/posts/oracle-cloud-postgresql-what-is-postgresql)) |
| nginx | 서버에 직접 설치 | 모든 요청의 입구, HTTPS 인증서 관리 |
| 정적 사이트 (React, Astro 빌드 결과) | Docker 없음 | 빌드된 파일을 nginx가 바로 보냄 |

Tomcat 9와 10.1을 서버에 직접 함께 설치하면 설정과 포트가 엉키기 쉽습니다. 컨테이너로 나누면 각자의 Tomcat이 서로를 모릅니다.

## 정리

- Dockerfile(설계도) → 이미지(틀) → 컨테이너(실행 중인 앱) 순서입니다.
- compose는 컨테이너 실행 옵션을 파일로 관리합니다.
- 컨테이너는 가상 머신보다 가볍고 빠릅니다.
- 이 시리즈는 Java 앱만 Docker로 나누고, 공용 서비스(nginx, PostgreSQL)는 직접 설치합니다.
