## 이 글에서 할 일

리눅스는 여러 사용자가 함께 쓰는 것을 전제로 만들어졌습니다. 그래서 "누가 어떤 파일을 읽고 쓸 수 있는가"를 엄격하게 관리합니다. 이 글에서는 권한을 읽는 법을 익히고, 비밀값 파일을 어떻게 보호하는지 정리합니다.

## 사용자와 그룹

- **사용자(user)**: 로그인하는 계정입니다. Oracle Cloud의 Ubuntu 서버는 기본 사용자 `ubuntu`로 작업합니다.
- **root**: 모든 권한을 가진 관리자 계정입니다.
- **그룹(group)**: 사용자를 묶은 단위입니다. 그룹에 권한을 주면 소속된 사용자 모두가 그 권한을 가집니다.

```bash
id
```

다음과 같은 형태로 나옵니다. 숫자와 그룹 목록은 서버마다 다릅니다.

```text
uid=1001(ubuntu) gid=1001(ubuntu) groups=1001(ubuntu),4(adm),27(sudo),989(docker)
```

이 중 중요한 그룹은 세 개입니다.

| 그룹 | 의미 |
|---|---|
| `sudo` | `sudo`로 관리자 권한을 쓸 수 있습니다 |
| `adm` | 시스템 로그(`/var/log`)를 읽을 수 있습니다 |
| `docker` | `sudo` 없이 `docker` 명령을 쓸 수 있습니다. Docker를 설치하고 직접 추가해야 생깁니다. **root와 같은 수준의 권한**이므로 주의가 필요합니다 |

## sudo

`sudo`는 "이 명령 하나만 관리자 권한으로 실행"한다는 뜻입니다. root로 계속 로그인해 있지 않고, 필요한 순간에만 권한을 빌려 씁니다. 실수로 시스템을 망가뜨릴 위험을 줄이는 방법입니다.

```bash
cat /etc/myapp/app.env          # 실패: Permission denied
sudo cat /etc/myapp/app.env     # 성공 (단, 비밀값이 화면에 나오므로 남이 볼 때는 실행하지 않습니다)
```

## 권한 읽기

`ls -l`로 보면 줄 앞에 `-rw-r-----` 같은 글자가 있습니다. 예를 들어 앱 하나를 운영하는 서버에서 다음 세 경로를 보면 이렇게 나올 수 있습니다.

```bash
sudo ls -l /etc/myapp/app.env
ls -ld /srv/myapp
sudo ls -ld /var/backups/myapp
```

실제 출력에는 날짜와 크기 열도 있지만, 여기서는 권한, 소유자, 그룹, 경로만 남겼습니다.

```text
-rw-r-----  root   docker  /etc/myapp/app.env
drwxr-xr-x  ubuntu ubuntu  /srv/myapp
drwx------  root   root    /var/backups/myapp
```

첫 글자는 종류(`-` 파일, `d` 폴더)이고, 나머지 9글자는 세 칸씩 끊어 읽습니다.

```text
-  rw-  r--  ---
│  │    │    └─ 그 밖의 모든 사람: 권한 없음
│  │    └────── 그룹(docker): 읽기만
│  └─────────── 소유자(root): 읽기, 쓰기
└────────────── 일반 파일
```

| 글자 | 파일에서 | 폴더에서 |
|---|---|---|
| `r` (read) | 내용 읽기 | 목록 보기 |
| `w` (write) | 내용 바꾸기 | 안에 파일 만들기, 지우기 |
| `x` (execute) | 실행하기 | 안으로 들어가기 |

### 왜 이렇게 권한을 주나

| 대상 | 권한 | 이유 |
|---|---|---|
| 비밀값 파일 (`app.env`) | 소유자 root 읽기/쓰기, docker 그룹 읽기 | DB 비밀번호 같은 비밀값이 있습니다. `docker compose`를 실행하는 사용자만 읽으면 됩니다 |
| 백업 폴더 | root만 모든 권한 | 백업에는 회원 정보 같은 데이터가 그대로 들어 있습니다. root 외에는 폴더 안을 볼 수도 없게 합니다 |
| 소스 코드 폴더 | 소유자 ubuntu, 나머지는 읽기 | 소스 코드는 비밀이 아니고, ubuntu 사용자가 `git pull`로 고칩니다 |

## 숫자로 쓰는 권한과 chmod

`r=4`, `w=2`, `x=1`을 더해 세 자리 숫자로도 씁니다.

| 숫자 | 글자 | 흔한 용도 |
|---|---|---|
| `600` | `rw-------` | 나만 읽고 쓰는 비밀 파일 (스왑 파일, 비밀값) |
| `400` | `r--------` | 나만 읽는 파일 (SSH 개인 키) |
| `640` | `rw-r-----` | 소유자 읽기/쓰기, 그룹 읽기 (`app.env`) |
| `755` | `rwxr-xr-x` | 누구나 실행할 수 있는 스크립트, 일반 폴더 |
| `700` | `rwx------` | 나만 쓰는 폴더 (백업 폴더) |

```bash
chmod 600 비밀파일             # 권한 바꾸기
sudo chown root:docker 파일    # 소유자:그룹 바꾸기
```

### umask: 새 파일의 기본 권한

백업 스크립트처럼 비밀 파일을 만드는 스크립트는 맨 앞에 다음 줄을 둡니다.

```bash
umask 077   # 앞으로 만드는 파일은 소유자만 읽고 쓰게
```

`umask 077`은 "앞으로 만드는 파일에서 그룹과 기타 사용자의 권한을 모두 뺀다"는 뜻입니다. 그래서 백업 파일이 처음부터 `600`으로 만들어집니다. 파일을 만든 뒤에 `chmod`하는 것보다 안전합니다. 아주 잠깐이라도 다른 사람이 읽을 수 있는 순간이 없기 때문입니다.

## 정리

- 일상 작업은 `ubuntu` 사용자로 하고, 관리자 권한은 `sudo`로 필요한 순간에만 씁니다.
- `rw-r-----`는 "소유자 읽기/쓰기, 그룹 읽기, 나머지 없음"입니다.
- 비밀값 파일은 `600`이나 `640`, 개인 키는 `400`, 비밀 폴더는 `700`으로 둡니다.
- `docker` 그룹은 root와 같은 수준의 권한입니다. 아무에게나 주지 않습니다.
