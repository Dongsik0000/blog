## 이 글에서 할 일

Ampere A1 서버는 ARM 프로세서(`aarch64`, `arm64`)를 씁니다. 대부분은 x86 PC와 똑같이 쓸 수 있지만, 미리 만들어진 실행 파일을 다룰 때 차이가 생깁니다. 이 글에서는 그 차이가 어디서 생기는지와 확인하는 방법을 정리합니다.

## 왜 차이가 생기나

프로세서마다 이해하는 **기계어**가 다릅니다. 같은 프로그램이라도 x86용으로 만든 실행 파일은 ARM에서 실행되지 않습니다. 영어로 쓴 설명서를 한국어만 읽는 사람에게 주는 것과 같습니다.

| 종류 | 예 | ARM 서버에서 |
|---|---|---|
| 소스 코드나 바이트코드로 배포되는 것 | Java `.war`, `.jar`, JavaScript, Python 코드 | 그대로 동작. 실행기(JVM, Node.js)만 ARM용이면 됨 |
| apt로 설치하는 프로그램 | nginx, PostgreSQL, Docker | Ubuntu가 ARM용을 제공하므로 그대로 설치 |
| 미리 빌드된 실행 파일 | Docker 이미지, 다운로드한 바이너리 | **ARM용이 있는지 확인 필요** |

## 서버의 아키텍처 확인

```bash
uname -m                     # 커널이 보는 이름
dpkg --print-architecture    # 패키지 관리자가 보는 이름
```

```text
aarch64
arm64
```

두 이름은 같은 뜻입니다. 리눅스 커널은 `aarch64`, Ubuntu 패키지와 Docker는 `arm64`라고 부릅니다.

## Docker 이미지와 아키텍처

Docker 이미지는 미리 빌드된 파일 묶음이라 아키텍처의 영향을 받습니다. 다행히 많이 쓰는 공식 이미지(tomcat, maven, eclipse-temurin, postgres, nginx 등)는 하나의 이름 아래 여러 아키텍처용을 함께 제공합니다. 이것을 **멀티 아키텍처 이미지**라고 합니다. ARM 서버에서 `docker pull`을 하면 자동으로 ARM용을 받습니다.

이미지가 어떤 아키텍처용인지는 다음 명령으로 확인합니다. `myapp:latest`는 확인할 이미지 이름으로 바꿉니다.

```bash
docker image inspect myapp:latest --format '{{.Os}}/{{.Architecture}}'
```

```text
linux/arm64
```

### 서버에서 직접 빌드하면 문제가 없습니다

앱 이미지를 **서버 안에서 직접 빌드**하면(`docker compose up -d --build`) 서버가 ARM이니 결과도 자연스럽게 ARM용이 됩니다. 문제는 **x86 PC에서 이미지를 빌드해 서버로 옮길 때** 생깁니다. 이 경우 서버에서 실행하면 아키텍처가 맞지 않는다는 오류가 납니다. 해결 방법은 두 가지입니다.

1. 서버에서 빌드합니다 (이 시리즈의 방식).
2. PC에서 빌드할 때 대상 아키텍처를 지정합니다: `docker buildx build --platform linux/arm64 ...`

### 이미지가 ARM을 지원하는지 확인하는 법

Docker Hub의 이미지 페이지에서 태그를 누르면 지원하는 OS/ARCH 목록이 나옵니다. 거기에 `linux/arm64`가 있으면 됩니다. 명령으로도 확인할 수 있습니다.

```bash
docker manifest inspect tomcat:10.1-jdk17-temurin | grep -A1 '"architecture"' | grep arm64
```

출력이 있으면 ARM용이 있다는 뜻입니다.

## 내 PC가 Apple Silicon 맥이라면

Apple M 시리즈 맥도 ARM입니다. 그래서 맥에서 빌드한 이미지는 서버와 아키텍처가 같습니다. 반대로 Windows나 Intel 맥(x86)에서 빌드한 이미지는 그대로 서버에 올리면 동작하지 않습니다.

## 정리

- Ampere A1 서버는 ARM(`aarch64` = `arm64`)입니다.
- Java, Node.js 코드와 apt 패키지는 신경 쓸 필요가 거의 없습니다.
- Docker 이미지는 ARM용이 있는지 확인합니다. 공식 이미지는 대부분 지원합니다.
- 이미지를 서버에서 직접 빌드하면 아키텍처 문제가 생기지 않습니다.
