## 이 글에서 할 일

클라우드에서 서버를 만들려면 네트워크 설정 화면을 반드시 거칩니다. 이때 `10.0.0.0/16`, 서브넷, 인터넷 게이트웨이 같은 단어가 쏟아집니다. 이 글은 그 단어들을 **택배 배송**에 빗대어 설명합니다.

## IP 주소: 집 주소

인터넷에 연결된 모든 기기는 **IP 주소**를 가집니다. `10.0.0.101`처럼 점으로 나눈 숫자 네 개입니다. 택배의 받는 사람 주소와 같습니다.

### 사설 IP와 공인 IP

| 구분 | 비유 | 예시 | 누가 접근할 수 있나 |
|---|---|---|---|
| 사설 IP | 아파트 안의 동, 호수 | `10.0.0.101` | 같은 네트워크 안에서만 |
| 공인 IP | 아파트 단지의 도로명 주소 | 인터넷에서 유일한 주소 | 인터넷 어디서나 |

서버의 사설 IP는 서버 안에서 확인할 수 있습니다.

```bash
ip -4 addr show
```

결과는 네트워크 카드마다 한 줄씩, 다음과 같은 형태로 나옵니다. 카드 이름과 주소는 서버마다 다릅니다.

```text
lo        127.0.0.1/8       ← 자기 자신을 가리키는 특별한 주소 (localhost)
enp0s6    10.0.0.101/24     ← Oracle Cloud가 준 사설 IP
docker0   172.17.0.1/16     ← Docker를 설치했다면 생기는 내부 네트워크
```

공인 IP는 서버 안의 네트워크 카드에 직접 붙어 있지 않습니다. Oracle Cloud가 공인 IP로 들어온 요청을 사설 IP로 넘겨 줍니다. 그래서 위 목록에는 공인 IP가 보이지 않습니다.

### 127.0.0.1 (localhost)

`127.0.0.1`은 "**나 자신**"을 뜻하는 주소입니다. 서버 안의 프로그램끼리만 통신할 때 씁니다. 이 시리즈에서 데이터베이스와 Tomcat을 `127.0.0.1`에만 열어 두는데, 그렇게 하면 외부에서는 아예 접근할 수 없습니다. 보안의 기본 원칙입니다.

## 포트: 집 안의 방 번호

한 서버에서 여러 프로그램이 동시에 통신합니다. 그래서 IP 주소만으로는 어느 프로그램에 전달할지 알 수 없습니다. 이때 쓰는 번호가 **포트**입니다.

| 포트 | 쓰임 | 이 시리즈의 권장 설정 |
|---|---|---|
| 22 | SSH (원격 접속) | 외부에 엶 |
| 80 | HTTP (웹) | 외부에 열고, HTTPS로 넘김 |
| 443 | HTTPS (암호화된 웹) | 외부에 엶 |
| 5432 | PostgreSQL | `127.0.0.1`에만 엶 |
| 8080 등 | Tomcat 같은 앱 서버 | `127.0.0.1`에만 엶 |

`주소:포트` 형태로 함께 씁니다. 예를 들어 `127.0.0.1:5432`는 "이 서버 자신의 5432번 방(PostgreSQL)"입니다.

## CIDR 표기: 주소의 범위

`10.0.0.0/24`처럼 슬래시와 숫자가 붙은 표기를 **CIDR**라고 합니다. "이 범위의 주소들"이라는 뜻입니다.

- 슬래시 뒤의 숫자는 **앞에서부터 고정된 비트 수**입니다. IP 주소는 총 32비트입니다.
- `/24`면 앞 24비트(숫자 세 개)가 고정되고, 마지막 숫자만 바뀝니다. `10.0.0.0` ~ `10.0.0.255`, 256개입니다.
- `/16`이면 앞 숫자 두 개가 고정됩니다. `10.0.0.0` ~ `10.0.255.255`, 65,536개입니다.
- `0.0.0.0/0`은 고정된 비트가 없으므로 **모든 주소**입니다. 방화벽에서 "누구나"라는 뜻으로 자주 씁니다.

## 서브넷: 동네 구획

큰 주소 범위(예: `/16`)를 작은 범위(예: `/24`)로 나눈 것이 **서브넷**입니다. 예를 들어 `10.0.0.0/16` 네트워크를 `10.0.0.0/24`, `10.0.1.0/24`처럼 나눕니다.

서브넷은 보통 두 종류로 나눕니다.

- **공용 서브넷(public subnet)**: 공인 IP를 붙여 인터넷과 직접 통신할 수 있습니다. 웹 서버를 둡니다.
- **사설 서브넷(private subnet)**: 인터넷에서 직접 들어올 수 없습니다. 보통 데이터베이스 전용 서버를 둡니다.

이 시리즈는 서버가 한 대라서 웹 서버와 데이터베이스가 같은 서버에 있습니다. 그래서 공용 서브넷 하나만 쓰고, 데이터베이스는 `127.0.0.1`에만 열어 보호합니다.

## 게이트웨이: 동네 밖으로 나가는 문

서브넷 안의 서버가 인터넷과 통신하려면 출입문이 필요합니다. 그 문이 **게이트웨이**입니다.

| 이름 | 하는 일 |
|---|---|
| 인터넷 게이트웨이 | 인터넷과 양방향 통신. 공용 서브넷이 사용 |
| NAT 게이트웨이 | 안에서 밖으로 나가는 것만 허용. 사설 서브넷이 업데이트 등을 받을 때 사용 |
| 서비스 게이트웨이 | Oracle의 다른 서비스(오브젝트 스토리지 등)와 내부망으로 통신 |

어느 문으로 나갈지는 **라우트 테이블**(길 안내표)에 적혀 있습니다.

## 방화벽: 경비실

**방화벽**은 들어오는 요청을 검사해서 허용된 것만 통과시키는 경비실입니다. "22, 80, 443번 포트로 오는 요청만 들여보낸다"처럼 규칙을 정합니다.

Oracle Cloud의 Ubuntu 서버에는 방화벽이 **두 겹** 있습니다.

1. **Oracle Cloud의 보안 목록**: 서버 바깥, 클라우드 네트워크에서 먼저 막습니다.
2. **Ubuntu의 iptables**: 서버 안에서 한 번 더 막습니다.

두 곳 모두에서 열어야 요청이 도착합니다. 이 내용은 [OS 방화벽 장](/posts/oracle-cloud-firewall-two-layers)에서 다시 다룹니다.

## 정리

| 용어 | 한 줄 요약 |
|---|---|
| IP 주소 | 기기의 주소. 사설 IP는 내부용, 공인 IP는 인터넷용 |
| 127.0.0.1 | 나 자신. 여기에만 열면 외부에서 접근 불가 |
| 포트 | 한 서버 안의 프로그램을 구분하는 번호 |
| CIDR | 주소 범위 표기. `/24`는 256개, `0.0.0.0/0`은 전체 |
| 서브넷 | 주소 범위를 나눈 구획 |
| 게이트웨이 | 서브넷 밖으로 나가는 문 |
| 방화벽 | 허용된 요청만 통과시키는 경비실 |
