## 이 글에서 할 일

나중에 도메인(예: `example.com`)을 서버에 연결할 때는 **공인 IP**를 DNS에 등록합니다. 그런데 공인 IP가 바뀌면 도메인이 엉뚱한 곳을 가리키게 됩니다. 이 글에서는 Oracle Cloud의 공인 IP 두 종류를 비교하고, 어떤 경우에 IP가 사라지는지 정리합니다.

## 두 종류의 공인 IP

공식 문서 "Public IP Addresses"의 내용을 정리하면 다음과 같습니다.

| 구분 | 임시 공인 IP (Ephemeral) | 예약 공인 IP (Reserved) |
|---|---|---|
| 수명 | 서버의 수명과 같음 | 직접 지울 때까지 유지 |
| 서버를 **중지**하면 | **유지됨** (서버에 계속 붙어 있음) | 유지됨 |
| 서버를 **종료**(Terminate)하면 | **삭제됨** | 남아 있음. 다른 서버에 다시 붙일 수 있음 |
| 다른 서버로 옮기기 | 불가 | 가능 |

**중지**(Stop)와 **종료**(Terminate)를 구분해야 합니다.

- **중지**: 컴퓨터 전원을 끈 상태입니다. 디스크와 설정은 남아 있고 다시 켤 수 있습니다.
- **종료**: 서버를 완전히 삭제합니다. 되돌릴 수 없습니다.

서버를 만들 때 "공인 IP 할당"을 선택하면 보통 **임시 공인 IP**가 붙습니다. 서버를 중지했다가 다시 켜는 정도로는 IP가 바뀌지 않습니다. 하지만 서버를 새로 만들어 옮기면 IP가 바뀝니다.

## 임시 IP를 예약 IP로 "바꿀" 수는 없습니다

공식 문서는 분명하게 적고 있습니다.

> 공인 IP 객체를 만든 뒤에는 종류를 바꿀 수 없습니다. 임시 공인 IP를 같은 주소의 예약 공인 IP로 전환할 수 없습니다.

그래서 IP를 고정하고 싶다면 **새 예약 IP를 만들어** 서버에 붙여야 하고, 이때 주소가 바뀝니다. 도메인을 연결하기 **전에** 결정하는 것이 좋습니다. 도메인을 연결한 뒤에 바꾸면 DNS도 다시 고쳐야 하기 때문입니다.

## 따라 하기: 예약 IP 붙이기

1. 검색창에 `Reserved Public IPs`를 입력해 이동하고 **Reserve Public IP Address**로 예약 IP를 만듭니다.
2. 서버(인스턴스) 상세 화면에서 **Attached VNICs** → 주 VNIC → **IPv4 Addresses**로 이동합니다.
3. 기존 임시 공인 IP를 해제(No public IP)하고, 만든 예약 IP를 선택해 붙입니다.

<!-- 📷 스크린샷: VNIC의 IPv4 주소 편집 화면 -->

> 예약 공인 IP의 무료 개수 한도는 공식 "Always Free Resources" 문서에 나와 있지 않습니다. 만들기 전에 콘솔의 한도(Limits) 화면이나 요금 안내를 확인합니다.
## 서버 안에서 공인 IP가 안 보이는 이유

서버 안에서 `ip addr`를 실행하면 사설 IP(예: `10.0.0.101`)만 보이고 공인 IP는 없습니다. Oracle Cloud가 공인 IP로 들어온 요청을 사설 IP로 바꿔서 전달하기 때문입니다(이 방식을 **NAT**, 주소 변환이라고 합니다). 공인 IP는 콘솔의 인스턴스 상세 화면에서 확인합니다.

## 정리

- 임시 공인 IP는 서버를 **중지해도 유지**되지만, 서버를 **종료하면 사라집니다.**
- 예약 공인 IP는 직접 지울 때까지 남고, 다른 서버로 옮길 수 있습니다.
- 임시 IP를 예약 IP로 전환할 수는 없습니다. 고정이 필요하면 도메인 연결 전에 예약 IP를 붙입니다.
- 공인 IP는 비밀값은 아니지만, 이 시리즈에서는 글에 적지 않습니다. 서버를 찾는 자동 공격의 대상이 되기 쉽기 때문입니다.
