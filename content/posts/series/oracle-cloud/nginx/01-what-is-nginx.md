## 이 글에서 할 일

서버 한 대에 정적 사이트 여러 개와 Java 앱(Tomcat)을 함께 올린다고 해 봅시다. 외부에서 들어오는 요청은 모두 **nginx 하나**가 받고, nginx가 알맞은 곳으로 나눠 줍니다. 이 글에서는 그 구조가 왜 필요한지 이해합니다.

## 웹 서버와 WAS

| 구분 | 하는 일 | 예 |
|---|---|---|
| 웹 서버 | 이미 만들어진 파일(HTML, CSS, JS, 이미지)을 그대로 보내 줌 | nginx, Apache |
| WAS (Web Application Server) | 요청마다 코드를 실행해 결과를 만들어 줌 (로그인, DB 조회) | Tomcat |

- React, Vue, Astro 같은 도구로 **빌드한 사이트**는 결과물이 파일이라 웹 서버만 있으면 됩니다.
- 로그인과 DB 조회가 있는 Spring 앱은 **Tomcat**이 Java 코드를 실행해야 합니다.

## 리버스 프록시

**프록시**(proxy)는 "대신 전달하는 사람"입니다. **리버스 프록시**는 서버 앞에 서서 손님의 요청을 받아 뒤쪽의 적절한 프로그램에 전달하고, 그 답을 다시 손님에게 돌려줍니다. 식당의 홀 직원과 같습니다. 손님(브라우저)은 주방(Tomcat)을 직접 보지 않고 홀 직원(nginx)과만 이야기합니다.

```text
브라우저 ── https://example.com/shop/ ──▶ nginx ── http://127.0.0.1:8080 ──▶ Tomcat
         ◀──────────── 응답 ─────────────        ◀────────── 응답 ──────────
```

## nginx를 앞에 두는 이유

| 이유 | 설명 |
|---|---|
| **HTTPS를 한 곳에서** | 인증서를 nginx에만 설치합니다. 뒤쪽 앱은 각자 인증서를 다룰 필요가 없습니다 |
| **주소 하나로 여러 앱** | `/app/`은 React 앱, `/shop/`은 Java 앱처럼 경로로 나눕니다. 도메인 하나로 여러 앱을 운영합니다 |
| **앱 서버를 숨김** | Tomcat은 `127.0.0.1`에서만 듣게 합니다. 외부에서는 nginx를 거치지 않고는 닿을 수 없습니다 |
| **정적 파일은 빠르게** | 빌드된 사이트와 업로드 이미지는 nginx가 직접 보냅니다. Java를 거치지 않아 빠르고 가볍습니다 |
| **공통 보안 장치** | 로그인 시도 속도 제한, 보안 헤더, 요청 크기 제한, 숨김 파일 차단을 nginx에서 일괄 적용합니다 |

## 이 장에서 만들 구성

이 장의 글들은 다음 구성을 예시로 설명합니다.

```text
                            ┌── /          → /srv/site (정적 파일, 메인 페이지)
                            ├── /docs/     → /srv/docs/dist (정적 파일, 빌드한 문서 사이트)
https://example.com ─▶ nginx ┼── /app/      → /srv/react-app/dist (정적 파일, React SPA)
                            ├── /shop/     → 127.0.0.1:8080 (Tomcat, Java 앱)
                            └── /uploads/  → /srv/uploads (사용자가 올린 이미지)
```

각 경로를 어떻게 설정하는지는 다음 글부터 하나씩 다룹니다. 자신의 서버에 맞게 경로와 폴더 이름만 바꾸면 그대로 쓸 수 있습니다.

## 정리

- 웹 서버는 파일을 보내고, WAS는 코드를 실행합니다.
- 리버스 프록시는 요청을 받아 뒤쪽 프로그램에 전달하는 대리인입니다.
- nginx를 앞에 두면 HTTPS, 경로별 분배, 앱 서버 숨기기, 보안 장치를 한곳에서 관리할 수 있습니다.
