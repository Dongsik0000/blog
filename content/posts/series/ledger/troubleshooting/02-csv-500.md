## 해결한 문제

CSV 내보내기 요청이 HTTP 500으로 실패했던 문제가 `1228b2b` 커밋에 기록되어 있습니다. 원인은 요청 파라미터 이름을 생략했는데, 해당 빌드에서 Java 메서드 파라미터 이름을 읽을 수 없었던 것입니다. 현재 코드는 `@RequestParam`에 이름을 명시해 해결했습니다.

당시 변경과 현재 코드의 선언을 연결해, 요청 이름을 명시하는 이유를 살펴봅니다.

## 요청의 이름과 Java 변수 이름

CSV 내보내기는 URL의 `from`과 `to`로 기간을 받습니다. Spring MVC는 이 요청 값을 메서드 인자에 넣어야 합니다.

이름을 생략한 `@RequestParam String from`은 프레임워크가 메서드 파라미터 이름을 알아낼 수 있는지에 영향을 받습니다. 당시 커밋 메시지는 `-parameters` 없이 컴파일된 상황을 원인으로 기록하고 있습니다.

## 현재 코드

`src/main/java/ledger/settings/controller/SettingsApiController.java` (CSV 메서드의 선언과 입력 해석)

```java
// 거래 CSV 내보내기(파일 다운로드, 읽기 전용이라 GET). 기간 오류는 400 오류 화면
@GetMapping("/export")
// 파라미터 이름을 명시한다(-parameters 없이 컴파일돼 이름을 알 수 없으면 500)
public void export(@RequestParam("from") String from, @RequestParam("to") String to, HttpSession session,
                   HttpServletResponse response) throws IOException {
    Map<String, Object> range = ParamUtil.map("from", from, "to", to);
    LocalDate fromDate = ParamUtil.date(range, "from");
```

원본 메서드의 앞부분 발췌입니다. `@RequestParam("from")`과 `@RequestParam("to")`가 요청 이름을 직접 정하므로 Java 변수 이름을 추론하는 데 의존하지 않습니다.

`value`가 요청 이름을 지정하는 `name`의 별칭이라는 점은 프로젝트 버전에 맞는 [Spring Framework 6.2.7 문서](https://docs.spring.io/spring-framework/docs/6.2.7/javadoc-api/org/springframework/web/bind/annotation/RequestParam.html)에서 확인했습니다(2026-10-07).

## 확인 방법

로그인한 상태에서 설정 화면의 CSV 내보내기를 엽니다. 조회할 기간을 선택해 내보내면 파일이 내려받아지고, 요청이 HTTP 500으로 실패하지 않아야 합니다.

다운로드한 파일의 열과 한글 표시도 확인합니다. CSV 필드의 문자 처리는 `CsvUtilTest`가 별도로 검사하며, HTTP 다운로드 확인과 단위 테스트의 역할을 구분합니다.

기록은 [해결 커밋](https://github.com/Dongsik0000/ledger/commit/1228b2b9af6f49ea7a2429d01f05d719f572c2ae)과 현재 `SettingsApiController.java`를 근거로 작성했습니다.
