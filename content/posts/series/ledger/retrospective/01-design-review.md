## 해결한 문제와 구현 연결하기

Ledger는 구글 시트에서 쓰던 가계부를 웹으로 옮기며 이월, 반복 입력, 월급 기준 주기를 구현한 프로젝트입니다. 이 글은 완성된 코드와 README에 기록된 내용을 기준으로 그 연결을 돌아봅니다.

이월 계산, 자동 기록, 공통 주기 계산, 실행 환경이 처음 해결하려던 불편과 어떻게 연결되는지 살펴봅니다.

## 이월은 거래를 기준으로 계산

달이 바뀔 때 남은 돈을 옮겨 적던 작업은 [시작 잔액과 이월 계산](/posts/ledger-domain-opening-balance)으로 해결했습니다. 기준일과 시작 잔액을 두고 거래 합계에서 잔액을 계산하므로, 과거 거래를 수정했을 때도 바뀐 거래가 계산에 반영됩니다.

이 원칙은 화면에 보여 줄 숫자를 따로 저장하기보다 그 숫자의 근거가 되는 기록을 유지하는 방식입니다. 통장 잔액도 기준 잔액, 거래, 이체를 연결해 계산합니다.

## 반복 입력은 일정과 처리 기록으로 해결

월세·통신비·월급을 매번 입력하던 작업은 [고정 항목](/posts/ledger-domain-recurring)과 스케줄러로 자동 기록합니다. 휴일 보정, 카드 할부, 달러 결제도 이 흐름에 연결되어 있습니다.

자동으로 실행하는 것만으로 끝나지 않고, 어떤 월의 항목을 처리했는지 `recurring_run`에 남깁니다. 이 처리 기록과 DB 제약이 함께 같은 달의 중복 거래를 막습니다. 정기 이체도 별도의 처리 기록을 사용합니다.

## 월급 주기를 계산의 공통 기준으로 사용

시작일이 1일인 달력 월과 실제 급여 흐름의 차이는 [PayCycle](/posts/ledger-domain-pay-cycle)에서 다룹니다. 같은 계산 결과를 대시보드, 거래 조회, 요약 통계에서 사용합니다.

날짜 계산은 짧은 달과 주말·휴일로 경계가 바뀝니다. 기존 JUnit 테스트가 이런 사례를 고정 입력으로 확인하므로, 화면을 볼 때마다 모든 날짜 조합을 손으로 확인하는 대신 계산 규칙을 반복해서 검증할 수 있습니다.

## 실행 환경까지 저장소에서 설명

앱은 WAR로 묶어 Tomcat에서 실행하고, Docker와 nginx로 서버에 연결합니다. 배포 스크립트와 GitHub Actions는 코드 갱신과 실행을 연결하고, 백업 타이머는 거래가 저장된 DB를 정기적으로 백업합니다.

서버별 DB 비밀번호와 API 키는 저장소 밖의 `/etc/ledger/app.env`에 둡니다. 따라서 완성된 코드를 실행하는 독자에게도 환경 파일 생성과 값 입력은 필요한 단계입니다. 이 준비 과정을 [배포 장](/posts/ledger-deploy-deploy-flow)에 명시했습니다.

## 이 프로젝트를 읽는 순서

기능을 이해하려면 README의 사용자 행동에서 시작해 Controller, 계산 클래스, 매퍼 SQL을 따라갑니다. 실행을 재현하려면 DB 준비와 환경 변수 입력부터 시작해 실제 로그인·조회로 확인합니다.

이 시리즈는 두 흐름을 같은 완성된 저장소에 연결합니다. 구현 설명은 실제 파일에서 확인하고, 개발 경험은 커밋에 남은 [해결 사례](/posts/ledger-troubleshooting-tomcat-shutdown-port)와 연결해 읽을 수 있습니다.
