## 이 글에서 할 일

Fashion Archive는 코디 사진을 계절과 품목별로 모으고, 사진마다 **"사진 속 아이템과 비슷한 제품" 링크**를 아이템 이름별로 묶어 두는 개인 큐레이션 사이트입니다. 이 글에서는 무엇을 만들었는지 먼저 둘러봅니다.

## 화면과 주소

`/login`, `/signup`을 뺀 모든 화면은 로그인이 필요합니다. 서버에서는 `/p1` 아래에서 서비스합니다.

| 주소 | 화면 |
|---|---|
| `/` | 내 코디 사진 전체 목록 |
| `/c/{slug}` | 카테고리별 목록. slug는 `spring`, `summer`, `autumn`, `winter`, `accessory`, `shoes` |
| `/photos/{id}` | 사진 상세와 아이템별 제품 링크 |
| `/admin/photos/new` | 사진 등록 |
| `/admin/photos/{id}/edit` | 사진 수정 |
| `/login`, `/signup` | 로그인, 회원가입(가입 코드 필요) |

## 주요 기능

| 기능 | 내용 |
|---|---|
| 사진 등록 | jpg, png, webp 사진(10MB 이하)과 제목, 메모. 카테고리는 여러 개 고를 수 있음 |
| 목록 | 최신순 그리드. 카드에 카테고리 색 점을 찍어 계절을 구분 |
| 제품 링크 | 아이템 이름(아우터, 바지 등)별로 묶어 표시. 링크마다 제품 이름과 메모 |
| 읽기와 편집 | 상세 화면은 기본이 읽기 모드이고, "편집"을 누르면 같은 화면에서 링크를 고침 |
| 계정 | 가입 코드가 있어야 가입. 로그인한 사용자는 자기 사진만 보고 고침 |
| 저장 | 사진은 서버 디스크의 사용자별 폴더에 저장하고, nginx가 정적 파일로 보냄 |

## 숫자로 보는 프로젝트

| 항목 | 값 |
|---|---|
| 개발 기간 | 2026-09-16 ~ 2026-10-06 (커밋 기준) |
| 커밋 | 35개 |
| 인원 | 1인 (설계, 개발, 배포) |

## 이 시리즈에서 다루는 것

| 장 | 내용 |
|---|---|
| 프로젝트 소개 | 기술 구성, 로컬 실행, 폴더 구조 |
| 전자정부 표준프레임워크 | 실행환경, Maven 의존성, 따른 관례, ledger와 비교 |
| Spring MVC 설정 | web.xml, dispatcher-servlet.xml, 컨트롤러, 인터셉터, 입력 검증 |
| Tiles 레이아웃 | Tiles 설정과 공통 레이아웃 |
| DB와 MyBatis | 테이블 설계, 다대다 관계, 본인 사진만 다루는 SQL |
| 사진 업로드 | multipart, 파일 형식 판별, 디스크 저장, 파일과 DB 맞추기 |
| 화면 | JSON으로 그리는 화면, 편집 모드, 정적 파일 버전 |
| 로그인과 보안 | 세션 로그인, 가입 코드, BCrypt, 링크 주소 검사 |
| 테스트 | 저장소의 JUnit 테스트 |
| 배포와 GitHub Actions | Dockerfile, compose, nginx, 자동 배포, 로그 |
| 겪은 문제와 해결 | 저장소 전환, 사진 403, 경로 404, 스크롤 문제 |

서버를 만드는 과정은 [Oracle Cloud 서버 구축](/series/oracle-cloud) 시리즈에, 같은 관례로 만든 다른 앱은 [Ledger](/series/ledger) 시리즈에 있습니다.

## 정리

- Fashion Archive는 코디 사진과 아이템별 제품 링크를 계절과 품목으로 정리하는 사이트입니다.
- 사진은 서버 디스크에 저장하고, 로그인한 사용자는 자기 사진만 다룹니다.
